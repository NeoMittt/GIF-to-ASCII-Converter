# GIF to ASCII Converter (`gif_to_ascii.py`)

Инструмент с графическим интерфейсом на `tkinter` для конвертации GIF-анимаций и статичных изображений в автономные Python-модули с ASCII-артом. Сгенерированные `.py`-файлы не требуют внешних библиотек (даже `Pillow`) и могут запускаться напрямую в терминале или импортироваться в другие проекты.

## Возможности

- **Графическое окно настроек (`tkinter` + `ttk`)**: удобный выбор ширины арта (`60`, `100`, `160` или `240` символов), переключение между монохромным и 24-битным цветным режимом (TrueColor ANSI) и диалог выбора файла.
- **Поддержка анимаций и фото**: чтение `.gif`, `.png`, `.jpg`, `.jpeg`, `.bmp`, `.webp` с автоматическим учётом EXIF-ориентации для одиночных снимков и корректным наложением прозрачности (`RGBA`) на чёрный фон.
- **Умное прореживание длинных GIF**: если в анимации больше 200 кадров, скрипт оставляет каждый $k$-й кадр ($k = \lceil n / 200 \rceil$) и суммирует задержки внутри группы, сохраняя исходную скорость воспроизведения.
- **Подавление мерцания и сглаживание шума**:
  - **Межкадровая стабилизация (`STABILITY = 16`)**: подавляет мелкий цветовой шум сжатия GIF между соседними кадрами.
  - **Построчная diff-перерисовка (`CLEAR_EACH_FRAME = False`)**: обновляет в терминале только те строки, которые изменились по сравнению с предыдущим кадром (включая плавный переход с последнего кадра на первый при зацикливании).
  - **Синхронный вывод (`\033[?2026h` ... `\033[?2026l`)**: группирует отрисовку кадра в единый атомарный буфер терминала.
  - **Сжатие ANSI-последовательностей**: цветовой код `\033[38;2;R;G;Bm` вставляется только при смене цвета соседнего пикселя в строке.
- **Полная автономность результата**: готовые файлы сохраняются в папку `ascii_arts/` и работают исключительно на стандартной библиотеке Python.

## Требования и установка

Для работы самого конвертера `gif_to_ascii.py` требуется **Python 3.10+** и библиотека **Pillow** (модуль `tkinter` входит в стандартную поставку Python):

```bash
pip install pillow
```

> На Linux при отсутствии `tkinter` его можно установить через пакетный менеджер (например, `sudo apt install python3-tk`).

## Использование конвертера

1. Запустите скрипт:
   ```bash
   python gif_to_ascii.py
   ```
2. В открывшемся окне **«ASCII-арт»**:
   - Выберите размер (по умолчанию **Средний — 100 символов**).
   - При необходимости отметьте **«Цветной режим»**.
   - Нажмите **«Выбрать файл…»** и укажите картинку или GIF.
3. Дождитесь завершения конвертации — скрипт создаст папку `ascii_arts/` рядом с `gif_to_ascii.py`, сохранит туда сгенерированный модуль (например, `ascii_arts/cat_ascii.py`), выведет его размер в консоль и предложит сразу запустить анимацию.

> Если файл с таким именем уже существует в `ascii_arts/`, к новому файлу автоматически добавится суффикс `_2`, `_3` и т.д. Имена без латинских букв/цифр автоматически преобразуются в `art_ascii.py`.

## Работа со сгенерированным `.py`-файлом

Каждый созданный в `ascii_arts/` файл полностью самостоятелен и не требует `Pillow`.

### 1. Прямой запуск в терминале

```bash
python ascii_arts/cat_ascii.py
```

- Анимация воспроизводится в бесконечном цикле до нажатия `Ctrl+C` (при выходе курсор и цвета терминала автоматически восстанавливаются).
- Если исходный файл — статичная картинка из одного кадра, арт выводится на экран и ждёт нажатия `Enter`.
- Если окно терминала у́же (`WIDTH`) или ниже (`HEIGHT`) самого арта, перед показом выводится подсказка с нужными размерами в символах и строках.

### 2. Импорт в собственный проект

Вы можете подключить сгенерированный модуль в любой другой Python-скрипт:

```python
from ascii_arts.cat_ascii import play, FRAMES, DELAYS, WIDTH, HEIGHT

# Проиграть анимацию один раз (последний кадр останется на экране)
play(loop=False)

# Проиграть в бесконечном цикле с полной очисткой экрана перед каждым кадром
play(loop=True, clear_each_frame=True)
```

### Параметры и константы внутри сгенерированного модуля

| Имя | Тип | Описание |
| :--- | :--- | :--- |
| `play(loop=True, clear_each_frame=CLEAR_EACH_FRAME)` | Функция | Запускает показ ASCII-арта в терминале. При `loop=False` проигрывает один раз. При `clear_each_frame=False` перерисовывает только изменившиеся строки поверх, при `True` — очищает экран перед каждым кадром. |
| `CLEAR_EACH_FRAME` | `bool` | Режим перерисовки по умолчанию (`False` — построчное обновление без мерцания). |
| `WIDTH` | `int` | Ширина кадра в символах. |
| `HEIGHT` | `int` | Высота кадра в строках. |
| `DELAYS` | `list[int]` | Список задержек каждого кадра в миллисекундах (минимум `20` мс). |
| `FRAMES` | `list[str]` | Список готовых многострочных ASCII-кадров (с ANSI-кодами в цветном режиме). |

## Настройка параметров конвертера (`gif_to_ascii.py`)

В начале `gif_to_ascii.py` доступны две константы для тонкой настройки рендеринга:

| Константа | По умолчанию | Описание |
| :--- | :--- | :--- |
| `PALETTE` | `" .:-=+*#%@"` | Набор символов от самого тёмного к самому светлому для расчёта яркости ($0.299R + 0.587G + 0.114B$). |
| `STABILITY` | `16` | Порог межкадрового сглаживания шума по каналам RGB (`0..255`). Если $\max(\|\Delta R\|, \|\Delta G\|, \|\Delta B\|) \le \text{STABILITY}$, пиксель сохраняет цвет из предыдущего кадра. Значение `0` отключает сглаживание. |
